# MIDI Studio — 性能計測（Phase 7, 2026-11-01）

REQ-NFR-03 / TEST_PLAN 8 の負荷曲で計測した結果。**値は計測した環境での実測で、他の環境での性能を保証するものではない。**

## 負荷曲（自作）

32 トラック、トラックごとに GS Reset 1 個・ノート 1,050 個・CC11 525 個（SMF のメッセージ数で約 10 万、モデル上のイベント 50,464 個）、テンポ変更 30 回。生成コードは `tests/integration/large-file.test.ts` と `tests/e2e/gs-quality.spec.ts`。曲の長さは約 9 分（30 分の曲は未計測。イベント数が同等なら処理時間はイベント数に比例する設計）。

## 結果

| 項目 | 環境 | 結果 |
|---|---|---|
| SMF 読み込み（コア、Node） | macOS / Node 22.16 / Vitest | 52 ms |
| SMF 書き出し（コア、Node） | 同上 | 27 ms |
| .midstudio 保存+読み込み（約 880 万文字） | 同上 | 78 ms |
| ファイル選択〜トラック表示（UI 込み） | Playwright headless Chromium / Firefox / WebKit | 134 / 137 / 123 ms |
| リストの DOM 行数（1 トラック 1,576 イベント） | 同上 | 19 行（表示範囲のみ、仮想化） |
| スクロール中のフレームレート（リスト / ピアノロール / トラックビュー） | 同上 | 60 / 61 / 60 fps（requestAnimationFrame の回数） |

## 注意

- フレームレートはヘッドレスブラウザでの requestAnimationFrame の回数で、実際の画面描画コストを完全には反映しない。実機の Chrome / Safari での体感確認は手動試聴チェックと合わせて行うこと。
- メモリ使用量（全体）は未計測。Undo 履歴については 2026-11-02 に計測した（下記）。

## 追記（2026-11-02、ADR-039）

同じ環境（Node 22.16 / Vitest、自作の 32 トラック・モデル上 100,800 イベントの曲）で計測。

| 項目 | 結果 |
|---|---|
| `.midstudio` の JSON 化（自動保存 1 回分） | 47 ms、17.0 MB |
| Undo 履歴 1 件あたりの保持メモリ（3,150 イベントのトラックを 1 か所編集） | 26 KB（500 件で 12.9 MB） |

- 履歴は「保持イベント数 200 万個（≒ 16 MB）」を超えると古い件から捨てる。直近 100 件は必ず残す。
- 自動保存の JSON 化はブラウザの空き時間（`requestIdleCallback`）に回す。
- ドラッグ中は画面内のプレビューのみで、SMF の書き出しは確定時に 1 回だけ行う（ARCHITECTURE J、ADR-019）。

## 追記（2026-11-04、ADR-076〜078 打ち込み支援）
