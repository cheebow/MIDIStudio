## 0. 製品方針・目的

### 0.1 目的

ユーザーが自分で入力したノートを、少ない操作で演奏らしい MIDI データに整える。編曲を「自動で作る」機能ではなく、**ユーザーの演奏意図を維持する MIDI 編集支援**として実装する。

### 0.2 設計原則

1. **シンプル**: 各機能は原則1つの小さなダイアログと少数の設定だけ。詳細パラメーターを大量に追加しない。
2. **既存操作と一体化**: ピアノロールの選択・編集コマンド・Undo/Redo・再生・保存・日本語/英語の仕組みを再利用する。
3. **選択範囲だけ変更**: 他トラック、未選択ノート、CC、SysEx、テンポ、拍子には触れない。
4. **標準 MIDI**: 確定結果は普通の Note On/Off + Velocity として保存でき、特定の SoundFont・ギター音源・キースイッチには依存しない。
5. **プレビューしてから適用**: キャンセルしても曲が変わらない。適用は1つのUndo単位にする。
6. **再現可能**: 同一入力と同一設定なら原則同一結果。揺らぎを付けるなら固定シードを使用する。
7. **既存機能を壊さない**: 元PPQ/絶対Tickと音源・Transportの責務を変更しない。
8. **既存機能と重複しない**: クオンタイズ、ヒューマナイズ、ベロシティ一括編集を作り直さず使い分ける。

### 0.3 スコープ

| ID | ユーザー向け機能 | 主な効果 |
|---|---|---|
| PT-01 | ギターボイシング | 選択和音を実際に押さえられるギターコードフォームへ変換 |
| PT-02 | ストラム（通常/カッティング） | リズムからダウン/アップを自動判定し、弦ごとの発音時刻・強弱・ゲートを生成 |
| PT-03 | アルペジオ | 選択和音を上昇/下降/往復の分散和音に変換 |
| PT-04 | レガート調整 | ノートの終了時刻を「つなぐ/重ねる/離す」に調整 |
| PT-05 | ベロシティ・シェイパー | 既存ベロシティを活かしてフレーズ全体に強弱の流れを付ける |

**メニューは5項目。カッティングは独立メニューにせず「ストラム」の奏法モードに含める。**

### 0.4 対象外

AI作曲、コード進行生成、丸ごとの自動伴奏、リアルなギターブラッシング音の合成、運指エディター、専用ギター音源の追加、ベース/ドラムの自動生成、プラグインホスト、オーディオトラック編集、独立した新規MIDIエンジン。

## 1. 既存アプリとの統合

### 1.1 現行コードを調べること

実装に先立ち、実際の **develop ブランチ（もしくは作業ブランチのHEAD）** を読み、以下を特定する。

- ノートデータ型（ID、絶対Tick、長さ、音高、Velocity、トラック・クリップとの関係）
- 選択中ノートの収集方法、およびクリップ境界/複数トラック選択の扱い
- 単一編集操作・Undo/Redo・Redo・連続ドラッグのトランザクション設計
- プレビュー実装（なければどの層に追加するのが小規模か）
- ピアノロールの右クリックメニューとローカライズ文字列
- 小節、拍、テンポ、拍子、PPQを取得するユーティリティ
- SMFのインポート/エクスポート、`.midstudio` 永続化、イベントIDの扱い
- 既存クオンタイズ、ヒューマナイズ、Velocity編集に流用できる処理
- テスト設計（Vitest、Playwright）とドキュメントの配置

**調査前に新しいディレクトリ名・型名・メソッド名を決め打ちしない。** 下記の型は概念モデルであり、現行実装に合わせること。

### 1.2 呼び出し場所

- ピアノロール: ノート選択時の右クリックに「打ち込み支援」サブメニューを追加。
- 既存の編集メニューがあれば同一コマンドにアクセスできる項目を設ける。別ロジックを持たせない。
- 選択ノートがないときは無効化。対象が不適切な場合は説明を表示。
- 初期対象はピアノロールからの選択。リストエディター等からの呼び出しは既存の共通選択APIが利用可能なら対応し、無理なUI増築はしない。

```text
打ち込み支援
├── ギターボイシング...
├── ストラム...                 ← 通常ストラム/カッティング共通
├── アルペジオ...
├── レガート調整...
└── ベロシティ・シェイパー...
```

### 1.3 全機能に共通するUI

- 既存デザインに統一した小さなダイアログ。
- 対象ノート数・対象コード数（該当時）を表示。
- 設定変更で結果を**ピアノロール上に仮表示**。適用前に本データと履歴へ書き込まない。
- 必須ボタンは「適用」「キャンセル」。試聴は現行の音源/Transportに安全に接続できる場合のみ追加（実装するなら副作用・鳴りっぱなし対策必須）。
- 処理不能な対象は理由を1文で表示し、無音の置換や推測による改変を行わない。
- 標準の確認ダイアログ、Undo/Redo、キーボードフォーカス管理を再利用。
- JIS/USキー設定、PCキーボード演奏モード、IME入力とショートカット競合を起こさない。

### 1.4 ステータス・保存

- 適用後すべての既存ビュー（トラック、ピアノロール、リスト、必要ならドラム）の表示が一致する。
- 再生キャッシュの更新規則は現行Transportの仕様を守る。必要なら停止/シーク時反映の既存方針に従う。
- `.midstudio` とSMFに変換後のノートが保存される。編集プレビュー用の一時メタデータをSMFに混入させない。

## 2. 共通処理モデル

### 2.1 変換単位

- `selectedNoteIds` を正本のイベント集合から解決し、該当ノートのスナップショットを得る。
- 変換関数は**純粋関数**を基本とする。入力を破壊せず、変更・追加・削除が必要なノートを「編集パッチ」として返す。
- 既存イベントIDは基本的に維持。ノート数が変わる変換では、対応する残存ノートIDを維持できる範囲で維持し、増加分には新規IDを割り当てる。重複ID禁止。
- 実行前に対象スナップショットとバージョン/リビジョンを検証。ダイアログが開いている間に対象が編集されたらプレビューを再計算するか適用を止める（古い状態を上書きしない）。
- 既存の同じTrack/Clip/EventStoreの所有権に従う。クリップ境界を跨ぐ変更は既存のイベント所属ルールに従い、失敗するケースは安全に通知する。

概念API（実際の名前は現行に合わせる）:

```ts
// 実装指示の概念型。既存の型・コマンドを優先する。
type TransformKind =
  | 'guitar-voicing'
  | 'strum'
  | 'arpeggio'
  | 'legato'
  | 'velocity-shaper';

interface TransformContext {
  ppq: number; // 楽曲から取得し、勝手に480固定へ変換しない
  tempoMap: unknown;
  timeSignatureMap: unknown;
  selection: readonly string[];
  seed?: number;
}

// transformNotes(notes, options, context) -> preview/result/diagnostics
// commitPreview(result) は既存編集コマンドへ1トランザクションとして渡す
```

### 2.2 Tick・テンポ・拍子

- ノート位置/長さは既存楽曲の**整数TickとPPQ**のまま計算する。
- 速度をミリ秒で指定する奏法は、ノート開始位置のテンポマップからTickへ変換。テンポ変更点をまたぐ場合も再生時間に整合する計算を使う。
- 拍アクセント/ストローク方向の判定は、曲頭からの絶対イベント番号ではなく**その位置の拍子と小節基準**で行う。
- プレビュー中に丸めたTickの誤差を蓄積しない。Tickは整数で、長さは最低1Tick。
- ノート音高0〜127、Velocity 1〜127、開始Tick≧0を保証する。

### 2.3 和音グループ化

- デフォルトは**同じ開始Tickの選択ノート**を1つの和音とする。
- 既存の微小な演奏ずれを含む場合でも扱えるよう、グループ化の寛容幅を内部で設けられる設計にする。ただし、異なるストロークや装飾音を誤結合しないよう、値は小さく保ち、グリッドや最小発音間隔に応じて上限を設定する。
- 異なるTrack/Clipをまたいで和音化しない。必要があればトラック/クリップごとに独立処理。
- 「和音が判定不能」「選択ノートが1つだけ」「時間的に重なりすぎている」等は機能ごとに明示したルールで処理。
- グループ同士の基準時刻と選択ノートの元時刻を保持し、同時刻近接補正でグルーヴが失われないようにする。

### 2.4 再適用・非破壊プレビュー

- プレビューは常に**適用前の元データ**から再計算し、設定を触るたびに加工が累積しない。
- 同一ダイアログ内で何度設定変更しても元データが変化しない。
- 適用後に再度同じ変換を行うときは、前回適用を自動検知できる情報がある場合は元タイミングから再計算する。情報がないインポートSMF等では**完全な冪等性を保証しない**。特にストラム再適用時には、既にノートが分散している場合の誤認識を避け、必要なら明示警告する。
- ランダム揺らぎは設定・seedに固定され、プレビューと確定結果が一致する。

## 3. PT-01 ギターボイシング変換

### 3.1 機能

選択された同時発音の和音を、**標準チューニング E2-A2-D3-G3-B3-E4**のギターで物理的に押さえられるコードフォームへ変換する。ギターで実際に鳴る各弦の音高を MIDI ノートに変換する。

### 3.2 UI

| 設定名 | 選択肢 | 初期値 |
|---|---|---|
| ボイシング | 自動／オープンコード優先／ハイポジション優先 | 自動 |

他のパラメーター（弦数、指番号、運指編集等）は初期UIに出さない。

### 3.3 音楽的ルール

1. 元の和音のピッチクラスを抽出し、ルートとコード品質を推定する。
2. 同一ピッチクラス集合が複数解釈できる場合（例: 相対的に曖昧な転回形）、入力最低音と近隣コードを参考にする。ただし勝手な大幅変更を避ける。
3. 初期対象は一般的な **maj / min / 7 / maj7 / m7 / sus2 / sus4 / dim / aug**。未対応コードは安全に処理不可とする。add9、9th、複雑なテンション等は無理に省略・置換しない。
4. 実際に同時押弦できる候補から選ぶ。各弦はミュート/開放/1つのフレット音に限り、各弦の音は最大1ノート。同じ弦を同時に2音鳴らさない。
5. 6弦を超える同時発音は禁止。開放弦と低フレットを優先するか、高いポジションを優先するかはプリセットに従う。
6. 必須構成音（基本的に3度、7thの区別等）を維持し、コード品質が変わる候補は選ばない。省略/重複は**コード品質と明示音の維持を優先**して限定的に許可。
7. 同時選択した連続コード進行は、フォーム間の移動距離もスコア化して、不自然に大きく跳ばないようにする。ただし絶対に最小移動を優先するのではなく、押さえやすさと響きを優先する。
8. 同一コードを複数回刻んでいる場合は、原則同じフォームを維持する。
9. 自信を持てる有効な候補がなければ元ノートをそのまま残し、プレビューに「この和音は変換できません」と表示する。

### 3.4 実装方針

- まず**確定的なコードフォームライブラリ**（メジャー/マイナー/7th等の代表フォーム）を実装する。オープンフォームと可動フォーム/バレーコードを区別する。
- 必要に応じて候補の探索を追加するが、候補数・最大フレット差・処理時間に上限を設ける。複雑な6弦全列挙を無制限に実行しない。
- 候補フォームに `stringIndex / fret / soundingPitch` を持たせる。発音順に使う弦情報はストラムのプレビューで利用できるよう、**同じ変換ワークフロー中のみ**伝播してもよい。
- `.midstudio` に弦配置を持続保存する場合は互換性とスキーマのversionを別途検討。**SMFには弦情報がないため、インポート後の完全な弦配置復元は保証しない**。
- ノート長とコード開始位置は原則維持し、音高と必要なノート数のみ変更する。元が4声でも結果が5声になることを許容。

### 3.5 受入例

- C major (C-E-G) → 標準チューニングで押さえられる C コードフォーム候補（例: x32010）を選べる。
- Am → 標準的な Am コードフォーム候補を選べる。
- C → Am → F → G を一括処理しても、コード品質が崩れず、押弦不可能な候補が出ない。
- 認識不能な集合や10音以上の不合理な入力では破壊的変換を行わない。

## 4. PT-02 ストラム変換／ギターのカッティング

### 4.1 機能

選択された和音の**元のリズム位置とコード進行を維持**し、ダウン/アップストロークの順番でノートの発音時刻を少しずらす。奏法を「カッティング」に切り替えると、短めのゲートとアクセントも付ける。

特に重要: **実際に鳴るコードを単純にD/U/D/Uと交互にしない。休符を含む仮想的な腕の往復に従う。**

### 4.2 UI（1つのダイアログ）

| 設定 | 選択肢 | 初期値 |
|---|---|---|
| 奏法 | 通常ストラム／カッティング | 通常ストラム |
| ストローク | 自動／ダウン固定／アップ固定 | 自動 |
| ストラム速度 | ゆっくり／普通／速い | 普通 |
| 自然な強弱 | ON／OFF | ON |
| カッティングのタイプ（カッティング時だけ） | ポップ／ファンク／ロック | ポップ |

デフォルトは「自動」。方向を1ストロークずつ手作業指定するUIは初期版では不要。

### 4.3 自動ダウン／アップ判定

1. トラック/クリップ単位で選択ノートを和音グループ化し、各グループの**元の発音基準位置**を取得する。
2. 小節と拍子を考慮して、各グループがどの拍・裏拍・細分に位置するか求める。
3. まず8分音符相当の刻みを基準にする。選択したフレーズに実際の16分刻みの打点がある場合は、16分音符単位の往復運動を基準にする。判定には音符位置の整数Tickを使い、少しずれたグルーヴを強引にクオンタイズしない。
4. 8分グリッドの場合: 8分インデックス偶数=Down、奇数=Up。16分グリッドの場合: 16分インデックス偶数=Down、奇数=Up。
5. **休符中にも腕の往復が続く**と仮定する。例えば 8分グリッドで `1 & 2 & 3 & 4 &` の `1, 2, 2&, 3, 4, 4&` だけ発音すると `D, D, U, D, D, U` になる。
6. 曲の途中から選択しても小節/拍の実際の位置を基準にし、選択先頭を無条件でDownにしない。
7. コードチェンジ、休符、シンコペーションをまたいでも、発音したイベント数ではなくグリッド位置から判定する。
8. グリッド判定があいまいな演奏（大量のオフグリッド、3連符、変拍子等）は、元リズムを動かさず**近い拍位置の規則的な方向**を選ぶ。方向が決まらない場合は安全にDownを採用し、必要ならプレビューで表示。推定のための元ノート量子化はしない。
9. 3/4、6/8等で小節が変わる場合も拍子マップの位置からインデックスを計算する。6/8では8分系を基本として扱い、3連符など複合拍子の詳細な奏法生成は後続改善とする。

> 注: 16分刻みで16分ごとにD/Uを交互にした場合、8分裏拍にもDownが来ることがある。これは採用する右手の往復モデルの結果であり、絶対的なギター演奏ルールではない。UIはシンプルに保ち、聴感で不自然なケースはテスト用パターンを追加して改善する。

### 4.4 ストラムのノート生成

1. Down: 低音弦 → 高音弦。Up: 高音弦 → 低音弦。
2. PT-01の弦配置情報を同じ編集操作の中で利用できるなら弦順を優先。情報がない通常MIDIコードは**低音程から高音程**を弦順の代替に使う。
3. 和音の基準Tickを最初の弦の発音位置として、ほかの弦を後ろへずらす。**曲頭の負Tickを作らない**。
4. 既定ストラム全体幅の目安: 速い=20ms、普通=45ms、ゆっくり=85ms。これらは固定の内部プリセットとし、テンポからTickへ換算する。実際の必要幅が隣のストローク間隔を超える場合は短縮する。
5. 各弦間の時間差は完全な等間隔にしない。自然な強弱ONのときは固定シードの小さな揺らぎを許す。ただし**音の発音順が逆転しない**。
6. ベロシティはコード全体の元強弱を尊重し、数値差は原則小さく。元のVelocityが1〜127から外れない。
7. ノート開始を遅らせても次のコード切替までに収まり、終了Tickが開始Tickより後になるようにゲートを調整する。元のゲートをできるだけ残す。
8. 自動ストローク方向だけの変更では和音のルートやコード品質、元リズムの基準時刻を変更しない。
9. 新規の短いノートを乱造せず、元選択ノートを中心に発音時刻を加工する。

### 4.5 カッティング

通常ストラムの実装を共通利用し、**追加処理はゲート短縮と強弱**に限定する。

| プリセット | ゲート感 | 強弱の方向 |
|---|---|---|
| ポップ | 程よく短い | 控えめで自然 |
| ファンク | 非常に短い | 裏拍・細かいアクセントを明瞭に |
| ロック | やや短い | 強めのアタックを優先 |

- 具体的なゲート比率・Velocity係数は音源で試聴して内部定数として定義し、コードコメントと単体テストに記録する。ユーザーにパラメーターを大量公開しない。
- 元のリズムとコード音は維持する。
- ノートを短くしてもすべて最低1Tickを保持し、次の発音と不自然に重ならない。
- 実機ギターのブラッシングノイズ/キースイッチ、ミュートサンプルは生成しない。GSギター音色で「カッティングらしい歯切れ」を表現する範囲に留める。

### 4.6 再適用注意

- 既に弦ごとに開始時刻がばらけているコードを、無条件に別々のコード群と認定しない。
- ダイアログ内のプレビュー変更は常に元データから再生成。
- 確定済みストラムへ再度適用する場合、変換履歴がなければ完全な元位置の復元は困難なため、誤った重ね掛けを避ける警告・安全策を実装する。**保存済みのSMFだけから100%再適用検出できるとは主張しない。**

### 4.7 受入例

```text
8分グリッド: 1  &  2  &  3  &  4  &
入力位置  : ●     ●  ●  ●     ●  ●
自動方向  : ↓     ↓  ↑  ↓     ↓  ↑
```

- 16分刻みの入力では16分グリッド基準になる。
- 裏拍だけ選択しても曲中の拍位置からUp/Downを決める。
- 曲途中/テンポ変更/拍子変更/休符あり/コードチェンジありでも再生位置と表示が一致する。
- 上記の方向とノート順が自動テストで検証される。

## 5. PT-03 アルペジオ変換

### 5.1 機能・UI

選択された同時発音和音を、各コードの範囲内で分散和音へ変換する。

| 設定 | 選択肢 | 初期値 |
|---|---|---|
| パターン | 上昇／下降／往復 | 上昇 |

### 5.2 処理

- 和音ごとに音高順へ並べる。上昇=低→高、下降=高→低、往復=低→高→低（折り返し端音の重複はしない）。
- 3音以上の往復では、必要数の追加ノートを生成することを許す。選択した元コードの**終端まで**に収める。
- 展開範囲の終端は、元コードの有効な終了位置と次コード開始位置の早い方を上限にする。ノート終端が揃っていない場合は、無理に長音を破壊せず、元コードのまとまりが推定できないならユーザーへ通知する。
- ステップは原則等間隔。ゲートは各ステップの約80%を内部初期値とし、最低1Tick。
- 和音開始位置、コード切替位置、構成音を変えない。テンポ/拍子を跨いでもTickに整合。
- 1ノートだけの選択では変換不要と表示する。
- 折返しの追加イベントには新規IDを割り当て、Undoで元コードの状態へ完全復元。
- 既存のSoundFontに依存しない。

### 5.3 非対象

リアルタイムに自動演奏し続けるMIDI FXプラグイン、ランダムパターン、オクターブ増殖、シーケンス自動伴奏等は作らない。

## 6. PT-04 レガート調整

### 6.1 機能・UI

ノート開始時刻/音高/Velocityを保ち、原則**ノートの終了時刻だけ**を変更する。

| 設定 | 動作 | 初期値 |
|---|---|---|
| つなぐ | 次の開始位置で終了する | ✓ |
| 少し重ねる | 次の開始位置より少し後で終了する |  |
| 少し離す | 次の開始位置より少し前で終了する |  |

### 6.2 処理

- 単音メロディは時間順にソートし、各ノートの終了位置を次のノートの開始位置から計算。
- 和音進行について、**同時開始かつ元の終端がほぼ揃うノート**は1つのグループとして扱い、次のコードグループ開始位置へ向けて終了を揃える。
- 独立した長いペダルトーンや内声が混在し、同一のコード終端と判断できない場合は、無理な一括短縮をしない。安全側に倒して対象外/確認メッセージを表示。
- 次のノートを選択していない場合は、そのノートを基準に未選択ノートを変更しない。最後の選択ノート/和音は原則変更しない。
- 同音連打は次のNoteOnへ適切につなぐが、NoteOffがNoteOnより後になるよう最低1Tickを守る。
- 「少し重ねる/離す」の内部初期値は時間基準で約15msを目安にする。選択位置のテンポからTick換算し、次のノートまでの間隔に対して上限を持たせる。
- すでにオーバーラップしているノートにも同じ目標終了時刻を設定するため、ダイアログでの再計算は累積しない。
- フレーズの休符を意図的に残したい場合は「少し離す」や範囲選択で対応。勝手な新規ノート生成はしない。

### 6.3 受入条件

- `C4 at 0 len 100`, `D4 at 120` に「つなぐ」→ C4終了Tick 120。
- 「少し重ねる」→ 次ノート開始より後、ただし有効Tick範囲内。
- 2和音/同音連打/選択境界/途中テンポ変更に対応。
- 元の開始Tick、音高、Velocityは不変。

## 7. PT-05 ベロシティ・シェイパー

### 7.1 機能・UI

既存ノートの速度値を活かしながら、フレーズの強弱パターンを適用する。

| プリセット | 効果 |
|---|---|
| クレッシェンド | 徐々に強く |
| デクレッシェンド | 徐々に弱く |
| 交互アクセント | 発音グループごとに強弱を交互に |
| 拍アクセント | 拍位置による強弱（強拍を強める） |

プリセット以外のパラメーターは初期UIに追加しない。

### 7.2 処理

- **開始位置/長さ/音高は変更しない**。Velocity（1〜127）のみを変更する。
- 和音に含まれるノートは同じ係数で増減させ、元の内声の強弱差を極力残す。
- クレッシェンド/デクレッシェンドは、選択範囲の最初〜最後の開始Tickに対して線形に緩やかなゲイン係数を変える。最初/最後の強弱を逆にしない。
- 交互アクセントは**同じオンセットの和音を1単位**とし、イベント単位でバラバラに強弱をつけない。
- 拍アクセントは曲の拍子マップに基づき強拍/弱拍を判定。4/4は第1拍を最強、第3拍を次の強拍、6/8は第1と第4の8分位置を相対的な強拍の目安とする。
- 元ベロシティに係数を掛ける方式を基本とし、全ノートを固定値に均すことはしない。
- 係数は内部定数として効果が過剰にならないように調整する（目安±10〜20%）。四捨五入して1〜127へクランプ。
- 既存のヒューマナイズと用途を分け、ここではランダム化を標準としない。
- 選択対象がすべて同一開始Tickの場合、クレッシェンド/デクレッシェンドは変化を作れないため、結果を無理に変えず説明する。

### 7.3 受入条件

- 3連続のノートでクレッシェンドは後半の相対音量が増加する。
- 和音内の2つの異なるVelocityは元の大小関係が保たれる（クランプ時を除く）。
- 交互アクセントは和音を1拍分の単位として扱う。
- 拍子変更後の拍アクセントは新しい小節定義に追従する。
- Velocityは常に1〜127。

## 8. 機能間の組み合わせ

- **PT-01 ギターボイシング → PT-02 ストラム**: 最も典型的な利用。元コードの拍位置を保ち、ギターの弦順にストラム。
- **PT-02 通常ストラム → カッティング**: 設定ダイアログ内の奏法切替で行う。いったん確定したストラムへの重ね掛けに依存しない。
- **PT-03 アルペジオ**は独立変換で、ストラムと同時に適用する自動チェーンは初期版では用意しない。
- **PT-04 レガート**と**PT-05 ベロシティ**は独立した選択ノート編集。対象が和音の場合のグループ化規則はそれぞれに従う。
- 複数のツールを適用する順序で結果が変わることはある。**自動で処理順を決めて複合適用するUIは作らない**。

## 9. 保存・障害対応・性能

### 9.1 保存互換

- ノートID/イベント構造は既存プロジェクトモデルに合わせる。
- `.midstudio`保存・復元、SMF Format 1書き出し・再読み込みで**音高・開始Tick・終了Tick・Velocityが意味的に一致**する。
- 元から存在したCC、Program Change、GS SysEx、未知Meta、テンポ、拍子、ポートメタは変換の影響を受けない。
- 変換メタデータや弦配置の持続保存が必要になった場合はプロジェクトschemaのマイグレーションを別途設計する。初版ではメタデータ保存を必須にしない。

### 9.2 エラー・キャンセル

- 選択空、単音のみ（和音系）、不正Tick、コード認識不能、変換結果0件、選択中に外部編集、対象クリップ操作不能は明示通知。
- キャンセル、Escape、ダイアログ閉じ、変換失敗で履歴や楽曲データは不変。
- 設定の変更を高速連打しても古いプレビューが新しいプレビューを上書きしない。
- 不正なNoteOffやノート鳴りっぱなしを発生させない。

### 9.3 性能

- 変換計算とプレビュー描画を分離する。大量選択でもUIを固めない。
- 目標性能: **選択1,000ノート程度の単純編集（ストラム、レガート、Velocity）が一般的デスクトップで体感待ちを生まない**。計測値は端末/ブラウザとともに残す。
- ギターボイシング探索は件数制限、候補数制限、重い計算のキャンセル手段を用意。計測が必要な場合は既存の性能テストに追加する。

7. 英語/日本語の表示、PC鍵盤モード・ドラムパッドモードへのキー操作影響を確認。

## 13. 仕様の優先順位と衝突時の判断

1. ユーザーの元データ保護、既存プロジェクトのデータ整合性を最優先。
2. 既存のMIDI Studioの正本データモデル・保存形式・Undo設計に従う。
3. 本文書の5機能の目的を維持する。
4. UIを複雑化する追加設定より、少ない設定で音楽的に無理のない既定動作を選ぶ。
5. 実装不能/判定不能なケースは黙って変換せず安全に通知する。
6. 未定義の細部は合理的な内部定数を選び、テストと変更履歴に記録する。
